# S Tunnel

Приложение для Windows 10/11. Весь сетевой трафик компьютера (любые программы, а не только браузер) идёт через ваш личный прокси (SOCKS5, HTTPS или HTTP), и реальный IP не утекает.

## Как устроена защита

| Канал утечки | Чем закрыт |
|---|---|
| Программы, которые не умеют работать с прокси | TUN-адаптер `STunnel`, через который система маршрутизирует **весь** трафик (sing-box, `auto_route` + `strict_route`) |
| Обрыв или падение ядра | **Kill switch** в Windows Firewall: исходящие соединения запрещены по умолчанию. Разрешены только трафик внутри туннеля, соединение ядра с прокси (для SOCKS5 также UDP к IP прокси) и DHCP. Если ядро упало, интернет пропадает, но реальный IP наружу не уходит |
| DNS | DNS-запросы перехватываются и отправляются как DNS-over-HTTPS **через прокси**. Порт 53 мимо TUN дополнительно блокируется через WFP |
| IPv6 | IPv6 тоже уходит в туннель, а прямой IPv6 закрыт брандмауэром |
| UDP: QUIC, WebRTC/STUN, звонки, игры | **SOCKS5:** идёт через прокси (UDP ASSOCIATE). **HTTP/HTTPS:** отклоняется, потому что метод CONNECT передаёт только TCP; браузеры сами переходят с QUIC на TCP. Мимо прокси UDP не уходит ни в одном режиме |
| Прочие разрешающие правила брандмауэра (Teredo, IP-HTTPS, правила других программ) | Пока защита включена, они временно отключены. При отключении защиты всё возвращается как было |

Проверка утечек прямо в приложении: внешний IPv4/IPv6, DNS-резолвер, UDP (через STUN: какой IP видят звонки и игры), а также попытка выйти в интернет напрямую с адреса физического адаптера (TCP и UDP). Такая попытка должна быть заблокирована.

## Установка

1. Скачайте `S-Tunnel-Setup-x.y.z.exe` из раздела **Actions → последняя сборка → Artifacts** или из **Releases**.
2. Установите. Приложение всегда запускается с правами администратора: они нужны для TUN-адаптера и брандмауэра.
3. Выберите протокол, введите адрес, порт, логин и пароль прокси. Нажмите **Подключить**.

Пароль хранится в зашифрованном виде через Windows DPAPI (`safeStorage`).

## Если интернет не вернулся

Например, если приложение удалили при включённой защите. Запустите
`C:\Program Files\S Tunnel\resources\scripts\emergency-restore.cmd`.
Он остановит ядро и вернёт брандмауэр в состояние до подключения (сохранено в `C:\ProgramData\STunnel\killswitch.json`).

## Ограничения (честно)

- **SOCKS5 не шифрует** канал до прокси: провайдер видит, что вы подключены к прокси, и имена сайтов (содержимое HTTPS-страниц всё равно зашифровано). HTTPS-режим шифрует канал, но не передаёт UDP.
- UDP через SOCKS5 работает, только если сервер поддерживает UDP ASSOCIATE и отдаёт ретранслятор на том же IP. Иначе UDP просто не работает (без утечки), и проверка утечек это покажет.
- IP скрыт, но это не полная анонимность: сайты по-прежнему видят отпечаток браузера, часовой пояс, язык системы и куки. Для этого есть S Browser.
- Правила брандмауэра из групповых политик (домен организации) приложение отключить не может.
- Одновременная работа с другим VPN или TUN-клиентом не поддерживается.

## Разработка

```
npm install
# положите sing-box.exe (1.13.x, windows-amd64) в папку bin/
npm test        # проверка генератора конфига
npm start       # из терминала, запущенного от администратора
```

Сборка установщика: GitHub Actions (`.github/workflows/build.yml`). Workflow скачивает sing-box, проверяет сгенерированный конфиг через `sing-box check` и собирает `.exe`. Тег `vX.Y.Z` создаёт релиз.

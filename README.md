# S Tunnel

Приложение для Windows 10/11. Весь сетевой трафик компьютера (любые программы, а не только браузер) идёт через ваш личный прокси (SOCKS5, HTTPS или HTTP), и реальный IP не утекает.

## Как устроена защита

| Канал утечки | Чем закрыт |
|---|---|
| Программы, которые не умеют работать с прокси | TUN-адаптер `STunnel`, через который система маршрутизирует **весь** трафик (sing-box, `auto_route` + `strict_route`) |
| Обрыв или падение ядра | **Kill switch** в Windows Firewall: исходящие соединения запрещены по умолчанию. Разрешены только трафик внутри туннеля, соединение ядра с прокси (для SOCKS5 также UDP к IP прокси) и DHCP. Если ядро упало, интернет пропадает, но реальный IP наружу не уходит |
| DNS | DNS-запросы перехватываются и отправляются как DNS-over-HTTPS **через прокси**. Порт 53 мимо TUN дополнительно блокируется через WFP |
| IPv6 | IPv6 тоже уходит в туннель, а прямой IPv6 закрыт брандмауэром |
| UDP: QUIC, WebRTC/STUN, звонки, игры | **SOCKS5:** идёт через прокси (UDP ASSOCIATE). **HTTP/HTTPS:** отклоняется, потому что метод CONNECT передаёт только TCP; браузеры сами переходят с QUIC на TCP. Мимо прокси UDP не уходит ни в одном режиме |
| Прочие разрешающие правила брандмауэра (Teredo, IP-HTTPS, правила других программ) | Пока защита включена, они временно отключены. При отключении защиты всё возвращается как было |
| Соединения, открытые до подключения | При подключении принудительно закрываются (IPv4); в проверке утечек есть отдельный пункт |

Проверка утечек прямо в приложении: внешний IPv4/IPv6, DNS-резолвер, UDP (через STUN: какой IP видят звонки и игры), а также попытка выйти в интернет напрямую с адреса физического адаптера (TCP и UDP). Такая попытка должна быть заблокирована.

## Исключения — без прокси

Приложения из раздела «Исключения» выходят в интернет напрямую, с вашим обычным IP. Всё остальное идёт через прокси. Это раздельное туннелирование (split tunneling): ядро sing-box узнаёт, какой процесс открыл соединение (`find_process`), и для путей из списка (`process_path_regex`) отправляет трафик в выход `direct`. Так работают TCP и UDP при любом протоколе прокси.

- Kill switch по-прежнему действует: прямой выход в брандмауэре разрешён только самому `sing-box.exe`, а программы не могут выйти мимо туннеля сами.
- DNS-запросы исключённых приложений, как и всех остальных, идут через DoH через прокси, так что провайдер не видит, какие сайты открываются.
- Изменения применяются сразу: ядро перезапускается, kill switch не снимается.

## Часовой пояс прокси

После подключения S Tunnel узнаёт часовой пояс по IP прокси (сервисы ipwho.is, ipapi.co, ipinfo.io, запрос идёт через туннель) и ставит его в Windows через `Set-TimeZone`. Название пояса для Windows берётся из встроенного в Windows ICU, а если его нет, то из таблицы. Время не меняется, только пояс. На время туннеля выключается служба автоопределения пояса `tzautoupdate`. Исходный пояс хранится в `C:\ProgramData\STunnel\timezone.json` и возвращается при отключении, при запуске S Tunnel без подключения и аварийным скриптом.

Большинство браузеров подхватывают новый пояс сразу. Некоторые приложения увидят его только после перезапуска.

## Только через S Tunnel

В разделе «Только через S Tunnel» можно выбрать приложения, которые работают только при включённом туннеле. Нажмите **«+ Добавить приложение»** и отметьте нужные в списке установленных. Список строится по меню «Пуск» и по установленным пакетам MSIX/Microsoft Store, так что в нём есть, например, Claude Desktop. Если приложения в списке нет, выберите папку, в которой оно установлено, или отдельный `.exe`.

Блокируется **всё приложение**, то есть все `.exe` в его папке или пакете: основная программа, вспомогательные процессы, программа обновления.

Защита не зависит от того, открыт ли S Tunnel:
- **Постоянное правило брандмауэра** (группа `STunnelOnly`) для каждого `.exe`. Оно блокирует исходящий трафик со всех локальных адресов, кроме адреса туннеля (`172.31.249.1`, `fdfe:5354:4e4c:1::1`) и loopback. Туннель включён — приложение работает через прокси, выключен — сети нет. Правило никогда не переключается.
- **Фоновая задача «S Tunnel Guard»** (`scripts/guard.ps1`, от имени SYSTEM, запускается вместе с Windows). Она закрывает выбранные приложения, если они запущены без туннеля или туннель пропал. Для нового `.exe` после обновления приложения она сразу добавляет правило, а каждые 2 минуты пересканирует папки и пакеты. Список приложений лежит в `C:\ProgramData\STunnel\apps.json`, менять его могут только администраторы.
- Аварийный скрипт защиту приложений не снимает. Снять её можно, только убрав приложение из списка или удалив S Tunnel.

Ограничения: в одном приложении учитывается не больше 400 `.exe`. Например, папка Steam вместе с установленными играми может не уместиться целиком. Слишком общие папки выбрать нельзя: Program Files, «Загрузки», Рабочий стол, профиль пользователя, весь диск. Системные программы и системные пакеты Windows добавить нельзя.

Приложения-пакеты (MSIX/Store) при каждом обновлении переезжают в новую папку версии. S Tunnel находит её через список пакетов Windows и переносит правила. Если приложение обновилось, пока S Tunnel был закрыт, правило для новой версии появится при следующем запуске S Tunnel.

## Установка

1. Скачайте `S-Tunnel-Setup-x.y.z.exe` из раздела **Actions → последняя сборка → Artifacts** или из **Releases**.
2. Установите. Приложение всегда запускается с правами администратора: они нужны для TUN-адаптера и брандмауэра.
3. Выберите протокол, введите адрес, порт, логин и пароль прокси. Нажмите **Подключить**.

Пароль хранится в зашифрованном виде через Windows DPAPI (`safeStorage`).

## Обновления

S Tunnel проверяет новые версии в GitHub Releases этого репозитория. Проверка идёт через 30 секунд после подключения, потом каждые 6 часов. Вручную можно проверить кнопкой в разделе «Обновления».
- Проверка и скачивание идут **только при включённом туннеле**: GitHub видит IP прокси, а не ваш реальный.
- Во время установки kill switch остаётся включённым. Новая версия после перезапуска подключается сама, поэтому нет момента, когда трафик идёт с реальным IP.
- Чтобы выпустить версию, поднимите `version` в `package.json`, обновите `CHANGELOG-latest.md` и сделайте push в `main`. GitHub Actions соберёт установщик и сам создаст релиз `vX.Y.Z`.

## Если интернет не вернулся

Например, если приложение удалили при включённой защите. Запустите
`C:\Program Files\S Tunnel\resources\scripts\emergency-restore.cmd`.
Он остановит ядро и вернёт брандмауэр в состояние до подключения (сохранено в `C:\ProgramData\STunnel\killswitch.json`).

## Ограничения (честно)

- **SOCKS5 не шифрует** канал до прокси: провайдер видит, что вы подключены к прокси, и имена сайтов (содержимое HTTPS-страниц всё равно зашифровано). HTTPS-режим шифрует канал, но не передаёт UDP.
- UDP через SOCKS5 работает, только если сервер поддерживает UDP ASSOCIATE и отдаёт ретранслятор на том же IP. Иначе UDP просто не работает (без утечки), и проверка утечек это покажет.
- IP скрыт, но это не полная анонимность: сайты по-прежнему видят отпечаток браузера, часовой пояс, язык системы и куки. Для этого есть S Browser.
- Правила брандмауэра из групповых политик (домен организации) приложение отключить не может.
- Одновременная работа с другим VPN или TUN-клиентом не поддерживается.

## Разработка

```
npm install
# положите sing-box.exe (1.13.x, windows-amd64) в папку bin/
npm test        # проверка генератора конфига
npm start       # из терминала, запущенного от администратора
```

Сборка установщика: GitHub Actions (`.github/workflows/build.yml`). Workflow скачивает sing-box, проверяет сгенерированный конфиг через `sing-box check` и собирает `.exe`. Тег `vX.Y.Z` создаёт релиз.
